# Product

## Register

product

## Users

PMs and compliance officers at organizations deploying AI systems. They use AML Studio during working hours, typically at a desk, reviewing and editing AI governance artefacts. They are non-technical but detail-oriented and trust-sensitive: they need to feel the tool is reliable and not going to trip them up.

## Product Purpose

AML Studio lets non-technical users create, edit, and version-control Agent Modeling Language (AML) artefacts stored in Git repositories. All changes flow through Git for governance and auditability. Success means a compliance officer can confidently manage AI agent definitions without needing to understand Git internals. The tool is distributed as a static file and runs locally.

## Brand Personality

Calm, authoritative, modern. Three words: **settled**, **precise**, **trustworthy**.

The logo is fixed and must not be changed. All colors, typography, spacing, and component choices are open to revision.

## Anti-references

- **Jira**: overwhelming information density, cluttered toolbars, too many competing actions on screen at once
- **Hacker / terminal aesthetics**: dark neon, dense monospace-first layouts, deliberately technical vibes that feel intimidating to non-developers
- Generic SaaS dashboard clichés: hero metrics, identical card grids, aggressive CTAs

## Design Principles

1. **Trust through clarity**: every element either builds confidence or is removed. Ambiguity in a governance tool is a defect.
2. **Progressive depth**: surface the essential, reveal detail on demand. Never confront users with Jira-style complexity upfront.
3. **Calm authority**: the interface should feel settled and professional, not busy. Confidence without noise.
4. **Accessibility as comfort**: WCAG AA minimum, AAA where practical. The goal is cognitive ease for everyone, not compliance checkboxes.
5. **Professional approachability**: governance work should not feel punishing. Modern and clean, but warm enough that non-technical users feel welcome.

## Accessibility & Inclusion

WCAG AA is the floor; aim for AAA where it does not create design conflicts. No specific accommodations required beyond the standard, but the tool should feel effortless: legible contrast, clear focus states, logical tab order, comfortable text sizing. The primary lens is cognitive comfort for all users, not targeted impaired-user compliance.
